# 历史题库完整词与释义重审设计

## 目标

以历史快照 `e242fe2` 的 151,663 道题为输入，只保留答案是完整词且 UTF-16 位置与经文一致的候选；为候选生成具体、可理解、但不包含答案原文的 `meaning`。任何不能可靠判断或不能安全释义的题均隔离，不进入发布快照。

## 范围与不可变约束

- 输入必须固定为 Git commit `e242fe2` 的 `quiz-bank.index.json` 所列全部 6 个题库分片，运行报告记录 commit、每个分片路径/SHA-256 和总题数。
- 候选必须同时通过：字段完整性、经文存在、UTF-16 切片等于 `word`、词典边界、严格结巴词边界、停用词/标点/过短通用词规则。
- 词典命中可证明完整专名或固定短语；结巴仅用于排除残词，不能单独用来修复或扩大候选。
- `meaning` 不能包含 `word` 或其规范化形式，不能等于或仅由泛化类别构成，且必须符合该题在该节经文中的实体、角色、关系、地点、事件或概念语境。
- 无法生成并通过验证的候选写入隔离清单及原因，不以“人名”“地名”等占位释义发布。
- 第一阶段只生成候选、改写和审计产物，不修改 `quiz-bank-*.json`、索引或线上 revision；发布是单独的人工确认步骤。

## 数据流

`e242fe2 历史题库` → `候选筛选` → `确定性位置/词边界审计` → `释义草稿输入` → `受约束释义重写` → `释义审计` → `高置信候选题库 + 隔离清单 + 统计报告`。

筛选器为纯 Python 模块，输出每题的 `CandidateDecision`。释义重写器不直接访问发布文件：它接收已通过的题、经文和词典元数据，产生带来源/规则版本的草稿；审计器决定接受或隔离。命令行工具把每一阶段落为 JSONL，保证可复跑和抽样复核。

## 完整词判断

1. 先使用现有 `slice_utf16` 检查位置。
2. 若答案与任意词典条目发生重叠但不完全覆盖同一词条，则拒绝为 `partial_lexicon_term`。
3. 若答案严格包含在一个结巴 token 内且不等于该 token，则拒绝为 `partial_segmented_term`；完整 token 不因相邻短 token 被误拒绝。
4. 拒绝标点、空白、停用虚词、单字泛名词和不含汉字/数字/拉丁字母的候选；词典中登记的单字专名可显式豁免。
5. 同一经文位置只保留一个候选；重复位置和无法确定词性者隔离。

## 释义重写与审计

重写必须结合基督教圣经知识，但事实依据按以下优先级固定：本节和相邻经文的明确语境 → 全书/全本圣经可核查的关系、职分和事件 → 经版本化词典条目。受限生成器只能据这些事实把内容写成简洁中文，不得臆造人物生平、地理位置、教义结论或跨传统争议解释；可核查事实不足时隔离该题。

重写优先级为：词典的结构化释义 → 经文上下文和圣经知识模板（人、地、族群、职分、制度、事件、概念）→ 受限生成器。每条释义要求至少有一个可核查的区分信息，例如人物的关系/职分/事件，地点的区域/事件/用途，概念的作用或神学语境。

审计拒绝：答案泄露、答案规范化泄露、只含禁用泛词、过短类别短语、缺少区分信息、与经文中答案出现位置不一致、生成器返回异常。释义中的直接经文逐字片段不得用作答案提示。

## 可审计产物

- `reports/historical-v1/input-manifest.json`：输入 commit、哈希、题数、词典/规则版本。
- `reports/historical-v1/candidates.jsonl`：每题的通过或隔离决定和原因。
- `reports/historical-v1/rewritten.jsonl`：通过候选的原释义、新释义、重写来源和审计状态。
- `reports/historical-v1/quarantine.jsonl`：所有隔离题及机器可读原因。
- `reports/historical-v1/summary.md`：按原因、书卷、词长、释义类型统计，并含固定随机种子的人工复核样本。

## 验收门槛

- 所有纳入候选的题通过现有结构/经文/UTF-16 验证。
- 新释义的答案泄露数、笼统释义数和无位置对应数均为 0。
- 报告能将每个历史题唯一映射为通过或隔离。
- 至少 100 条固定种子样本（覆盖人物、地名、族群、职分、概念和普通词）被列入报告供人工审阅；人工批准前不发布替换快照。
